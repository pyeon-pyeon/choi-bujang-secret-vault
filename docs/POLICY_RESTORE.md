# 시험 정책의 검증 사본 비교·복원

현재 프로젝트에는 침해 전에 검증한 실제 안전 사본과 독립 보관한 신뢰 지문이 없습니다. 현재 정책을 자동으로 안전 사본으로 지정하지 않습니다. 아래 도구는 준비된 사본에만 사용합니다. 지문 검증은 파일 무결성과 승인 기록의 동일성을 확인하며 정책의 안전성을 새로 증명하는 검사는 아닙니다.

안전 사본 폴더에는 `aleph.config.json`, `src/decider.mjs`, `manifest.json`이 필요합니다. manifest 형식은 `schema: vault.safe-policy.v1`, `version: 검증된 전체 커밋 SHA`, `verifiedAt`, `incidentAt`, `files: [{path, sha256}]`입니다. 검증 시각이 침해 시각보다 앞서야 하고 두 정책 파일의 해시가 일치해야 합니다. manifest의 SHA-256 지문은 침해 전에 별도 승인·보관한 값으로 입력하며 사본과 함께 새로 만든 지문을 신뢰 근거로 삼지 않습니다.

1. 읽기 전용 비교: `node scripts/policy-diff.mjs <안전사본폴더> <신뢰manifest지문>`. 복원 버전과 변경된 파일·줄 구간만 출력합니다. 정책 원문·비밀값은 출력하지 않습니다.
2. 독립된 시험 폴더를 준비합니다. 운영 프로젝트 자체는 대상이 될 수 없습니다. 시험 폴더의 `policy-test.json`은 `{"schema":"vault.isolated-policy-test.v1","operational":false}`여야 합니다. 이 표시는 격리 시험 폴더를 지정하기 위한 것이며 안전 사본 승인 대신 사용하지 않습니다.
3. 실행 전 확인: `node scripts/policy-restore.mjs <안전사본폴더> <신뢰manifest지문> <시험폴더>`. 복원 버전·서비스·파일 목록·확인 지문을 검토합니다. 이 호출은 쓰지 않습니다.
4. 검토한 변경만 실행: 위 명령 끝에 출력된 `confirmationSha256`을 붙입니다. 계획·현재 정책이 달라지거나 검증이 실패하면 중단합니다.
5. 복원 후 시험 폴더에서 A의 본인 요청 허용, B의 A 요청 거부와 기존 다른 서비스의 응답 유지 여부를 시험합니다. 실제 자료 API의 소유자 검사도 별도 확인합니다. 실측하지 않은 시험은 완료로 기록하지 않습니다.

복원 범위는 메모 서비스만입니다. 안전·현재 판정기를 각각 보존하고 메모 요청은 안전 판정기로, 다른 서비스 요청은 이전 판정기로 위임합니다. 설정은 메모의 allowedRoutes만 교체하고 다른 설정·서비스 경로·감사 로그·DB 자료는 유지합니다. 추가 보관 모듈을 덮어쓰지 않습니다. API·DB를 복원하는 도구는 아닙니다.

가상 임시 폴더에서 사전 확인 지문 필수, A 허용·B 거부, 다른 서비스의 step_up 유지, 다른 설정과 감사 로그 보존을 시험했습니다. 실제 안전 사본으로 현재 자료실을 복원하거나 운영 정책을 변경한 것은 아닙니다.
